Arcadia Demo Deck

Eleven independent modules. Each one names a problem, the command that answers it, and why it lands — so you can pick as the conversation goes rather than follow a script. Every timing here is measured wall time against a byte copy of the live workspace. Nothing merges, deploys, spends, or sends.

The one rule for improvising

Green cards are read-only — run them in any order, as many times as you like, nothing changes. Red cards write state — each is a one-shot, and everything they create comes out with the single undo command at the bottom. If you are unsure mid-demo, reach for a green card.

Only I touches the network (it fetches from origin). Everything else is local SQLite and local git. No card makes a model call.

The modules

A

What needs me right now

Read-only2.6s · 4 lines
The problem

You have twenty minutes and no idea where they should go.

Type
arcadia mission-control overview
Shows

Four lines: 5 thing(s) need you, then Life, Projects and Decisions counts.

Why it lands

“Four lines. Not a dashboard I have to interpret — a number I can act on. Everything else is one level down if I want it.”

B

The whole portfolio at once

Read-only2.2s · 51 lines
The problem

Four projects, and no one person can hold all four states in their head.

Type
arcadia portfolio
Shows

Four active projects with open / in-progress / blocked / done counts and a clarity breakdown, then 16 open Decisions, then 60 Actions in flight; 28 ready to work, 35 not yet.

Why it lands

“Twenty-eight are ready to work and thirty-five aren’t — and it knows the difference. That’s the only reason I can leave a project for three weeks and come back.”

“And those sixteen are questions it needs me for. It stopped and asked instead of guessing.”

C

What this repo says to do next

Read-only3.2s · 72 lines
The problem

Re-deriving context every time you open a project — or every time an agent does.

Type
arcadia docket
Shows

Active plan, token impact, milestone, the current Action, its next action, five acceptance criteria, the authorization line, then the standing constraints from CONSTITUTION.md.

Why it lands

“One command, no model call, tells me the plan, the current action, and what ‘done’ means for it.”

Scroll to the bottom — this is the line for a tooling builder: “And that’s the constitution, printed with every dispatch. The agent doesn’t have to remember the rules. The rules ship with the objective.”

D

Same command, any repository

Read-only3.4s · 66 lines
The problem

Per-project tooling that has to be reinvented per project.

Type
arcadia docket --repo ~/Dev/PrivatePracticeNow/platform
Shows

A different project, plan and current Action — including one 1020-character next-action paragraph. Do not read it. Let it fly past.

Why it lands

“Same command, different repository, different truthful answer. That paragraph is what a coding agent gets handed — I didn’t write it this morning, it accumulated. All of it cost zero model tokens.”

E

Raw notes become routed work

Writes state1.3s · 13 lines
The problem

You think in sentences on your phone. Those notes pile up somewhere and nobody ever files them.

Type — show the folder first
ls ~/Dev/MR/Arcadia/demo-ingress/DemoNotes/In

arcadia ingress process --ingress-root ~/Dev/MR/Arcadia/demo-ingress --source DemoNotes --stable-seconds 0
Shows

Discovered: 3 · Processed: 3, then one line per file. Three plain-text notes become three different things:

pinterest.txt     → an Action, open, in Rebuster
intake-link.txt   → Back Burner Question → Private Practice Now
weekly-digest.txt → Back Burner Idea    → unscoped

Confirm the routing with arcadia back-burner list --project private-practice-now.

Why it lands

“Three sentences I typed on my phone. It decided one was work, one was a question, and one was just an idea — and it filed two of them against the right project without me naming the project. One point three seconds, and no model was called.”

Know this before you run it

This reads a local folder, not iCloud. The real source is an iCloud Drive folder, and iCloud sync is exactly the dependency a live demo shouldn’t carry — a note that hasn’t finished downloading is a dotfile placeholder, and the scanner skips dotfiles. Say “this folder syncs from my phone” only once the iCloud path is confirmed working. Byte-identical across two clean runs, so it is safe to rehearse.

F

Park an idea against a condition

Writes state2.7s · 21 lines
The problem

The good idea you have mid-conversation that is genuinely not now.

Type — live, in front of her
arcadia ask "Try the docket output on a second screen at reading distance before the next demo" --back-burner --surface-date 2026-09-08
Shows

Execution path: Back Burner, Result: Captured in Back Burner., and a new bb_ id.

Why it lands

“Out of my head in two seconds, with a date attached. It is not on any list I have to read between now and September the eighth.”

Fallback

Timed at 0.94s, 0.94s and 0.99s across three runs, no model call. If it somehow errors, say “I’ll do that one after” and move to G — the point still lands on the item that already fired.

G

Only what has become relevant

Read-only2.6s · 12 lines
The problem

Every backlog you have ever kept became a graveyard you stopped opening.

Type
arcadia back-burner list --fired yes
Shows

Exactly one item — the --brief idea, with Surface: date 2026-08-21 — fired. Not the twenty-odd others that are still waiting.

Why it lands

Slowly. “I had that idea yesterday. It was good, and it was not what I was doing, so I gave it a condition — come back on the twenty-first — and I forgot it completely. Today is the twenty-first.”

“Most tooling has nowhere to put the good idea that isn’t now. It becomes a TODO nobody reads, or it’s gone. This is a third option: park it against a condition and actually forget it.”

H

A condition fires in front of her

Writes state4.2s · 23 lines
The problem

“Remind me when X happens” is a thing every tool promises and none of them actually do.

Type
arcadia work done $DEMO_ACTION

arcadia back-burner list --fired yes
Shows

Completed Action: Deliver the 10-minute Arcadia demo to a technical peer, then the list goes from one item to two — the new one reading Surface: dependency "Deliver the 10-minute Arcadia demo to a technical peer" = done — fired.

Why it lands

“This demo was itself an Action in the portfolio, and I’m marking it done because it is. I never scheduled that second idea. I attached it to a condition — when the demo is done — and the condition just happened, in front of you.”

One-shot

Once the Action is done the condition stays fired; you cannot replay this card without re-seeding. Save it for the close.

I

Nothing destructive without asking twice

Read-only4.5s · 15–19 lines
The problem

Agent sessions leave worktrees and branches everywhere, and cleaning them up by hand is how you lose work.

Type — from ~/Dev/MR/Arcadia/arcadia
arcadia tidy
Shows

Where the live work is, then Would retire (N) naming why each is safe — “every commit is already on main” — then Nothing was changed.

Why it lands

“It can tell finished work from live work, it tells me why each one is safe, and it changed nothing. Everything destructive here makes you ask twice.”

The only card that touches the network — rehearse the Ctrl-C

It fetches from origin. If it hasn’t painted in about five seconds, Ctrl-C and run the offline version, timed at 1.34s:

arcadia tidy --no-fetch --no-github

Never run --apply during the demo. Refusing to is the point.

J

Fail-closed handoff to a coding agent

Read-only1.1s · 15 lines
The problem

Starting an agent session on the wrong branch, in the wrong worktree, against stale state.

Type
arcadia go
Shows

Base and source worktree, Integration: not-needed, Preview only: no branch, worktree, or commit was changed, Dispatchable: yes, the current Action, its expected Artifact, and the exact prompt to hand the agent.

Why it lands

“It reconciles the git state first and tells me whether the next action is even dispatchable — before an agent touches anything. And like everything else, it previews: nothing moved until I add --apply.”

K

A parked idea becomes real work

Writes state1.3s · 4 lines
The problem

“So it resurfaces — then what?” The obvious next question after G or H.

Type
arcadia back-burner promote $DEMO_BB_BRIEF
Shows

Back Burner item promoted. plus the new Action id and its title, derived from the original note.

Why it lands

“One command and it stops being an idea. It’s an Action in the portfolio now, and it shows up in everything you just saw.”

Follow it with B to show the count moved.

If you want a close

“Everything you just saw ran on this laptop, against SQLite and git, and cost zero model tokens — the models only get called when something actually needs judgment. What I don’t think you can buy anywhere is that one thing: a place to put an idea that names the condition that should bring it back, so I can genuinely stop thinking about it. That’s what lets one person run a portfolio instead of a project.”

After the demo · one command

~/Dev/MR/Arcadia/arcadia/scripts/demo/unseed-2026-08-21.sh --apply

Previews without --apply. Removes everything cards E, F, H and K can create: the Back Burner rows marked source_ref='demo-2026-08-21', the rows marked ingress_source='ingress:DemoNotes', the Action ingress created, the seeded demo Action, and the staged notes folder. Verified as a round trip against a copy of the live workspace, leaving all 25 pre-existing Back Burner items untouched.

Deliberately not removed: the Action Schedule an Arcadia demo for a non-engineering audience and the Back Burner item waiting on it, which carries the founder/PM and leadership scenario sets. Real deferred work with a real trigger.
