# Hand-off: plan close-out record (2026-10-13)

- `arcadia plan close-out <plan-slug> [--write] [--json]` writes
  `docs/plans/<plan-slug>.close-out.json` deterministically; `pnpm check:plan-close-outs`
  validates records in CI. Read-only by default.
- A record carries `ledger.evidence` (none | partial | complete); aggregates are null when
  none. The hardening Plan's backfill is evidence none: no ledger row cites its Action ids
  (0 of 32), so its record is honest but thin. A selector must treat `evidence: none` as
  unknown, not clean.
- PRs per Action come only from ledger rows and from merge commits that actually contain
  a completion sha; settle commits land directly on main, so most done Actions show no PR.
- A close-out record is a snapshot: renaming a Plan Action later fails the validator with
  the remedy to delete and re-run the command.
- Next for the selector Action (`next-plan-selector`, attention until this lands): read
  `closed`, `openRemainders`, `ledger.evidence`.
