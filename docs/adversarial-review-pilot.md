# Adversarial review pilot for consequential plans

This draft records a process tried on production hardening. It does not alter the Constitution, adopt new Project rules, require two reviews for ordinary work, or approve a reviewed proposal.

Use it when a complex, costly decision has credible alternatives. First confirm the Outcome and Milestone through the existing planning process. Do not re-interview questions the operator already answered.

1. Freeze a short packet: confirmed requirements, important Decisions, source revision, observations, uncertainties, alternatives, budget and the concrete choice. Date later evidence as addenda.
2. Give one fresh reviewer the packet and read-only access. Ask for at most five important findings and the cheapest discriminating test for each. Require the strongest argument for keeping what exists and which work can be eliminated.
3. Give a second fresh reviewer the original packet and first report. Ask it to try to falsify the claims, identify missing guards, separate source risks from reproduced incidents and recommend the smallest useful change. Disagreement is useful only when supported.
4. Adjudicate evidence, not votes. For each retained finding state: entry preconditions → strongest blocking guard → effect and replay path → what remains untested. Reject speculative scope and preserve unresolved disagreement.
5. Produce one pragmatic recommendation: vital few changes first, observable acceptance, owner, dependencies, costs, deferral triggers and the exact remaining human judgment. Map it to existing Actions before drafting a canonical Agent Ask. Review output is never execution authority.
6. Run the smallest fault tests. Repair demonstrated defects and review the code normally. Measure the next installed trial separately from hermetic simulation. Record whether this review prevented work, changed a decision or merely added cost.

Keep reports bounded and avoid recursive agents. Use a third pass only when a specific missing fact could change the choice. Prefer deterministic investigation for code mechanisms; reserve frontier reviewers for judgment and consequential design. Record models, elapsed time, operator interventions, and actual usage when available; missing cost data remains missing.

The first pilot preserved the host/Project/candidate architecture, exposed unsupported completion inference, and removed speculative engine and identity-migration work. Repeat on another high-value case before building automatic routing or a mandatory review workflow.
