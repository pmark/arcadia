# Decision 0173: Decide what authority Rowan holds for a day at a time over unattended work on the critical path, so that routine operational steps stop waiting on the operator.

## Options

- **A. Daily grant: START and routine run operations** (recommended): The operator's own message in Rowan's chat or press on /actions approves one day: 24 hours from that approval, never self-renewing, and Rowan cannot grant it. That approval is the run's activation touch. Within it, on the active Plan's critical path at concurrency one, Rowan may: press START cards it prepared, each after a fresh pre-mortem, preflight and pin check; retry after a failed attempt once it has named the cause, stopping for the operator if two attempts fail on the same cause; turn production Off to end a stuck or failed attempt; re-run a failed or never-started required check once per head when the cause is not attributed to the candidate; and reset an Action's repair budget once per Action per day after naming and fixing the cause. Rowan's merges stay exactly as they are under the standing gate: independent review of the current head, required checks green, clean merge. Rowan still may not answer a Decision, merge a pull request that carries a Decision or that the blast-radius assessment marks authority-adjacent, reset a consumed START allowance, probe credentials, use paid fallback, run runtime recovery, grant itself a merge exception or bypass an approval, deploy or publish. Attempts count across days, and at Decision 0170's three Rowan stops and the operator decides. All of these powers end at hour 24: a run already started keeps running on its own grant, its merges stay under the standing gate and Decision 0171's Off at scope complete still applies, but anything else waits for the operator or a new day's approval. Each use is recorded on the coordination Issue and alerted on Discord. A run that needed a repair-budget reset or a mid-run Off is not a clean run. An operator STOP or Off ends the day. Risk: Rowan could spend all three attempts within hours, before the operator sees them, and each START may renew the shared Claude sign-in.
- **B. Daily grant: START and retries only**: The operator's own message or press approves one day, as in the first option, with the same exclusions and the same end at hour 24. Rowan may press prepared START cards, after the same checks, and retry after a failed attempt once it has named the cause, within Decision 0170's limit. Ending a stuck attempt, resetting a repair budget and running a never-started check still wait for the operator, so a hold like the one on 2026-11-04 would still wait for the operator.
- **C. No grant: keep each press with the operator**: Nothing changes. Every START, retry and reset waits for the operator, and Decision 0171 still lets Rowan issue the Off at scope complete and re-run an unattributed failed CI job once per head. It is the most supervised option, and it keeps the delays the operator asked to remove.

## Rationale

Operator, in Rowan's chat, 2026-11-04: "I just don't see the value in repeatedly waiting for me to start when I definitely would do it ASAP. For tomorrow and moving forward, please make it so that I can approve unattended work on the critical path for a day at a time." And later: "let's give you the authority to make decisions like this in the future so that we don't have long delays that serve no real purpose again." On 2026-11-04 attempt 1 waited about six hours, from the worker's 10:41 UTC escalation, on a hold with one sensible answer. Rowan recommended the first option. It covers the operational calls the operator named. It declines the wider reading of that request: Rowan gets no authority over Decisions, which the Constitution keeps with the operator, and any wider authority needs its own Decision and a Constitution change. The critical path is the active Plan's governed queue. This grants nothing until the operator answers it and the delegation is built, in a separate reviewed pull request, on Decision 0163's delegated press. Option A changes these records. It makes the day's approval the separate START approval the AGENTS.md production directive requires. It supersedes Decision 0171's rule that each retry needs an operator press, and widens Decision 0163's scope; Decision 0163's other conditions stand, including that each blocking defect is fixed through a reviewed pull request before a successor, and that an operator STOP, a Decision, a stop-the-line or a refused host permission ends the delegation. It reads the directive's bar on attempt reset as covering an Action's repair budget, and lifts it only for the reset it names; every other bar stands, as does Decision 0163's exclusion of resetting a consumed allowance. It does not change Rowan's merge authority under Decisions 0060 and 0080, or Decision 0170's definition of a clean run.
