# Decision 0214: Which merge route should unattended production's worker use for candidate pull requests that change source code (src/**), which today can never merge without the operator?

## Options

- **A. Worker merges src/** changes that touch no authority boundary, on the same proof gates as today (recommended)** (recommended): The worker may merge a candidate whose every changed path is under src/** (plus the tests and docs it already accepts), is not classified by `classifyAuthorityPaths` and is not on the existing governance/excluded lists, but only when the recorded independent code review and QA bind the exact head with no blocking finding, every required check is green, the merge state is CLEAN, the Active scope's `mergeThroughPullRequest` grant is on, and the blast-radius assessment is not authority-adjacent; any refusal sends the PR to the operator's batch-merge card as today. Largest unlock: ordinary code Actions merge unattended and the operator stops being the bottleneck for them. Residual risk: the path classifier becomes the only guard for source, so a src module that enforces a gate but sits outside the classified prefixes would merge unattended; an audit Action listing gate-enforcing src modules outside the classified prefixes runs before the allowlist change and adds any it finds to the classifier. Implementation is a source change to `isWorkerMergeSafePath` in `src/production/` (an authority path), so it needs the operator's own merge. Every option keeps excluded, unchanged: any path `classifyAuthorityPaths` classifies (project governance, Decisions, agent guidance, permissions, `src/production/`, `src/decisions/`, `src/ask/`, `src/cli/`, `src/identity/`, `src/server/`, `src/operatoractions/`, `scripts/`, `bin/`, dashboard mutating routes, `.arcadia/`, `.github/`, dependency manifests, deploy config), the Constitution, and any pull request that opens or carries an important Decision or changes what agents are authorized to do; no spend, credentials, deployment, publication or messaging authority is granted.
- **B. Worker merges only an explicit allowlist of source paths (tests-adjacent and named low-risk modules)**: Same proof gates as option A, but `isWorkerMergeSafePath` accepts only src paths on a named allowlist the operator approves now (for example pure helpers and formatting modules, each path justified); any other src change waits for the operator's merge, and widening the list needs a later Decision. Unlocks the safest slice of code Actions and cannot silently cover a gate-enforcing module, but every Action touching an unlisted module still stalls on the operator and each widening spends an operator Decision. Same implementation need as A: an operator-merged change in `src/production/`. Every option keeps excluded, unchanged: any path `classifyAuthorityPaths` classifies (project governance, Decisions, agent guidance, permissions, `src/production/`, `src/decisions/`, `src/ask/`, `src/cli/`, `src/identity/`, `src/server/`, `src/operatoractions/`, `scripts/`, `bin/`, dashboard mutating routes, `.arcadia/`, `.github/`, dependency manifests, deploy config), the Constitution, and any pull request that opens or carries an important Decision or changes what agents are authorized to do; no spend, credentials, deployment, publication or messaging authority is granted.
- **C. Keep today's route: the operator merges every source change**: No change: `isWorkerMergeSafePath` keeps accepting only tests, ordinary docs and non-governance top-level Markdown, so every candidate touching src/** is recorded authority-adjacent and waits for the operator's batch-merge card (or a Decision 0182 standing-order merge by Rowan outside a run window); unattended production keeps stalling on every code Action whenever the operator is away. Nothing new to build or review, and the guard stays at its strictest. Every option keeps excluded, unchanged: any path `classifyAuthorityPaths` classifies (project governance, Decisions, agent guidance, permissions, `src/production/`, `src/decisions/`, `src/ask/`, `src/cli/`, `src/identity/`, `src/server/`, `src/operatoractions/`, `scripts/`, `bin/`, dashboard mutating routes, `.arcadia/`, `.github/`, dependency manifests, deploy config), the Constitution, and any pull request that opens or carries an important Decision or changes what agents are authorized to do; no spend, credentials, deployment, publication or messaging authority is granted.

## Rationale

Rowan 3 ranked a merge route for source changes the single biggest unlock for unattended production: the worker's allowlist (`WORKER_MERGE_SAFE_PATHS`, src/production/workerMerge.ts:188; `isWorkerMergeSafePath`, :213) deliberately contains no src/** or apps/** path (comment at :177, 'every module can define or enforce a gate'), and `assessWorkerMergeBlastRadius` marks any non-allowlisted agent path authority-adjacent (:300-303), so `evaluateWorkerMerge` refuses with `authority_adjacent` (:156-158). Decision 0176 states no option changes this allowlist, which stays tests and ordinary docs. The path classifier `classifyAuthorityPaths` (src/decisions/batchMerge.ts:204, with EXACT :80 and PREFIXES :113) already names the authority-gated source prefixes and runs on top of the allowlist (:298). Recommendation A: the proof gates (exact-head independent review and QA, green required checks, CLEAN merge state, blast radius) carried the worker's recorded merges so far (tests and docs only), the classifier already fences the modules that define or enforce authority, and C leaves unattended production blocked on the operator for every code Action. Choosing A or B changes what agents are authorized to do (CONSTITUTION.md:14 excludes such pull requests from the standing merge exception), so recording the answer and the follow-on change to `isWorkerMergeSafePath` are the operator's merge; neither merges on the standing exception. Production stays Off pending separate START approval and this Decision does not change that.
