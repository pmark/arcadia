# Turn an outside article into a development blog note

Use this procedure when an operator gives you an article for their project blog.
An article supplied to Clara in a Field Notes editorial context is enough to
start a draft. Resolve the assigned Project, blog, audience, editorial rules,
topic taxonomy and Resources catalog from existing project records. If the
destination is ambiguous, prepare the analysis and ask where to place it.

1. Read the original. Record its linked title, author, publisher and date when
   available. If you cannot read enough to verify its claims, ask for a copy.
2. Extract the few insights that matter to the blog's readers. Explain them in
   your own words and use a concrete example. Attribute the author's findings
   and distinguish your interpretation.
3. Connect the ideas to the Project. Cite repository evidence for current
   behavior and state what that evidence proves. Describe a nearby enhancement
   or an aspirational direction when appropriate, clearly marking it as a
   proposal and explaining how readers could tell whether it works.
4. Draft in the blog's normal format. Assign relevant existing topic tags.
   Add or reuse the canonical source in the blog's existing Resources catalog
   and pair it with the draft using the catalog's conventions. If the blog has
   no catalog, preserve the citation in the draft and surface the missing
   capability through the existing proposal path.
5. Check citations, tags, the catalog pairing and the boundary between current
   and proposed behavior. Hand back the draft and catalog paths, validation
   results and any remaining publication gate. Follow the blog's existing
   review and publication procedure. An intake request authorizes draft
   preparation within its scope.

For Arcadia Field Notes, follow the [site contract](../../site/README.md).
Use a dated draft in `docs/articles/`, one to three topic slugs, and a source
entry in `site/_data/resources.yml` linked by post slug. Resources only displays
sources paired with a published post. Resolve publication separately under
Clara's [editorial guidance](session-roles-and-briefs.md#clara-technical-writing).
