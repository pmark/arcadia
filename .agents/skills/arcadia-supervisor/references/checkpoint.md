# Derived supervisor milestone checkpoint

This is an evidence projection for continuation. It cannot grant authority,
mark an Action done, change a pointer, or replace canonical receipts.

Store one small Markdown or JSON checkpoint in an already authorized handoff
location. Keep private evidence within its existing custody boundary. Link the
path in the manager chat so a fresh session can find it. If no safe file path
exists, retain the same fields in the final chat handoff. Do not create a new
live workspace or put runtime state in this skill's installation directory.

## Fields

- **Target:** repository, Project, exact milestone, current Plan/Action, and
  canonical source revision/time. State any discrepancy with the operator's
  requested target.
- **Acceptance boundary:** mandatory criteria and source references; proposed
  or deferred expansion and triggers; unresolved scope/authority questions.
- **Gap table:** requirement key/source, mandatory or conditional, status,
  dependencies, evidence URI/path and revision, owner/chat ID, next safe move,
  and gate. A gap may be a missing proof rather than missing implementation.
- **Watchlist:** Project/Plan/Action, canonical Session and native chat IDs,
  candidate identity, last verified progress/time, actual observed state,
  latest cursor, and any inaccessible source. Include pending create/handoff
  operation IDs to prevent duplicate dispatch.
- **Blockers:** stable identity, first observed/last verified, exact failure,
  evidence, attempted recovery, owner, smallest unblocker, affected requirement
  keys, authority needed, custody, and reactivation event.
- **Authority:** direct operator instructions and governing receipts with scope,
  expiry and prerequisites. Explicitly distinguish preparation, messaging,
  dispatch, settlement, merge, installation and activation. Capability is not
  authorization; an inherited summary needs its supporting instruction/receipt.
- **Operator actions:** exact reviewed action ID/title, final descriptor/script
  or Decision reference, live listing verification time, preconditions,
  consequence, and available/running/succeeded/failed state. Preserve failed
  receipts; disable/reject stale choices rather than presenting them anew.
- **Notifications:** last alert signatures and resolution receipts, last full
  checkpoint time, requested cadence, automation ID/state, and stop/resume
  instruction. An unchanged blocker is not a new alert.
- **Continuation:** next dependency-ready move, owner, verification command or
  supported route, stop condition, and model/effort only when inference is
  actually needed. Deterministic preparation needs no coding model.

## Fresh-session procedure

Read this projection, then re-read current authority and changed canonical
sources. Verify pending operation outcomes, consumed buttons, candidate claims
and the last known session states before retry or dispatch. Re-derive invalidated
evidence and update the gap. Do not automatically resume a paused automation.

## Decision checks

Before handing off, verify these outcomes against the actual records:

- An active chat only waiting on CI does not count as observed coding progress.
- A successful three-Action rehearsal cannot close unrelated literal browser or
  continuation criteria; approval of scope cannot count as live execution.
- A proposed requirement is conditional until its canonical acceptance, and
  a deferred requirement stays deferred until its recorded trigger/transition.
- A partial launch/settlement/publication failure is recoverable from its exact
  receipt; never repeat acceptance or dispatch merely because a response was lost.
- A consumed or stale button is not an operator choice. If listing cannot be
  verified, hand off the verification gap rather than claiming availability.
- When permission to message is absent, prepare the exact continuation for
  human authorization without sending it. When a finite coordination grant is
  present, use it without repeatedly asking for the same authority.
- When the operator says stop, pause the schedule before other work and preserve
  enough state to resume later. Installing this skill never restarts the watch.
